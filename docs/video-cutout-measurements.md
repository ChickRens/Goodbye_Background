計測のやり方は `worker/measure/README.md`。計測コードは `worker/measure/measure_app.py`（本番と同じ `worker/cutout/` の部品を使う）。

## 再計測（原因の切り分け、2026-11-06）

GPU を `["L4", "A10G", "T4"]`（空いている順に使う）に変え、Python が動く前の時間を分けて測った（`measure_app.py::probe --rounds 3`）。

| 項目 | 値（中央値） |
|---|---|
| GPU の割り当て待ち（最小イメージ・GPU あり） | 2.6 秒 |
| CUDA イメージの上乗せ（GPU あり − 最小） | −0.1 秒（別にモデル読込 1.2 秒） |
| slim イメージの上乗せ（GPU あり − 最小） | −0.4 秒（別にモデル読込 0.8 秒） |
| 割り当てられた GPU | 12 回中 A10(G) が 11 回、L4 が 1 回 |

- slim イメージ（Debian + ffmpeg 7.1.5 + pip の CUDA / cuDNN）でも zscale あり・CUDA でモデルを読めることを確認。
- **前回の遅さ（150〜724 秒の Pending）は L4 の割り当て待ちが原因**で、イメージの大きさは関係なかった。

## 判断基準

- **コールドスタート（送受信を除く推定）≤ 60 秒 → Modal で続行**
  - 送受信を除く推定 = コールドの差（手元の所要 − サーバー処理）− ウォームの差の平均。
    差には手元 PC からの動画のアップロードと出力 mp4 のダウンロードが入るが、本番のワーカーは R2 から取るので除く
  - あわせて「モデル読込」「起動→準備完了」の列も見る（Python が動く前のコンテナ起動分は差にしか現れない）
- 60 秒を超えたら Modal のメモリスナップショット（`enable_memory_snapshot`）を試して再計測する
- それでも超えるなら作業を止めてオーナーに報告する（RunPod への切り替えは計画の変更として扱う）

## コールドスタート

差 = 手元で測った呼び出しの所要時間 − サーバー側の処理時間（コンテナ起動・モデル読込・動画の送受信を含む）。
送受信を除く推定 = コールドの差 − 同じ実行のウォームの差の平均（判断にはこちらを使う）。

| 動画 | 回 | 差(s) | 送受信を除く推定(s) | モデル読込(s) | 起動→準備完了(s) |
|---|---|---|---|---|---|
| A: 標準設定（HDR のつもりだったが入力は SDR） | 1 | 682.6 | **666.2** | 3.3 | 3.3 |
| B: 60fps | 1 | 182.7 | **150.6** | 0.9 | 0.9 |
| C: 途中から入る | 1 | 735.4 | **724.1** | 1.4 | 1.4 |
| D: 緑っぽい服（点の指定ミス） | 1 | 274.6 | **214.7** | 1.4 | 1.4 |

- 計測中、Modal の画面ではコンテナが **Pending** のまま長く待たされた（オーナーの観察）。
- モデル読込・起動→準備完了は 1〜3 秒。**時間のほぼ全部が Python が動く前（GPU の割り当て待ち・イメージの配布）** にかかっている。
  メモリスナップショットは Python 起動後を短くする仕組みなので、この遅さには効かない見込み。

## 判断

- **コールドスタートは 150〜724 秒で、基準の 60 秒を大きく超えた。** ただしモデル読込は 1〜3 秒で、
  原因は Python が動く前（Pending = GPU の割り当て待ち、または大きな CUDA イメージの配布）にある。
- ウォームでの速度・精度・費用は目標を満たす（10 秒の動画でサーバー処理 約 18 秒、見失い 0、約 0.6 円）。
- 判断基準どおり作業を止めてオーナーに報告し、オーナーは「原因の切り分け」を選んだ（常時起動は月 約 $575 のため見送り）。
- **再計測の結果、コールドスタートは 5.3 秒（送受信を除く推定）で基準の 60 秒を満たした → Modal で続行する。**
- 本番も GPU は `["L4", "A10G", "T4"]` のフォールバックにする（L4 だけに絞ると割り当て待ちで数分〜10 分以上待たされる）。
  イメージは実ジョブで確認できた slim を使う。常時起動（min_containers）は不要。
- 費用は A10G / T4 に割り当たると単価が L4 と変わるが、1 本 数セント未満で 1 円未満の目標の範囲に収まる見込み（請求画面で要確認）。
- HDR の実機ファイルでの確認は未実施（4 本とも SDR だった）。
