# 動画切り抜き: 選んだ範囲だけを切り出してアップロードする（設計）

- 日付: 2026-11-12
- 状態: オーナー承認済み（チャットで案 A「範囲だけを切り出して送る。再エンコードしない」を選択）

## 1. 目的

アップロードに数十秒かかる。今は元の動画ファイルを丸ごと（最大 200MB）送っているが、使うのは選んだ 10 秒だけ。
スマホの中で選んだ範囲を含む部分だけの MP4 を作って送り、送る量を減らす。映像・音声のデータはそのまま写す（画質は変わらない）。

## 2. 決めたこと

| 項目 | 決定 |
|---|---|
| どこで切るか | ブラウザ（`frontend/js/video/trim.js`）。サーバー（Rust）とワーカーは変えない |
| 作り方 | 元のファイルの `moov` を自前で読み、選んだサンプルだけの表を持つ新しい `moov` を書く。中身（`mdat`）は元の File の `slice` を並べた Blob（メモリに読み込まない） |
| 切る位置 | 映像は「表示時刻が開始以下の、最後のキーフレーム」から。終わりは範囲の終わり + 1 秒まで。音声も同じ時間を含む分 |
| 時刻 | 新しいファイルの時刻 0 = 切り出しの先頭のキーフレーム（元の時刻 O ミリ秒）。ジョブの時刻（範囲・フレームの点）は全部 `元の時刻 − round(O)` で送る。画面（範囲のスライダー・フレームの選択）は元の動画のまま |
| 残すトラック | 最初の映像と最初の音声だけ（iPhone の時刻コード・メタデータのトラックは捨てる） |
| 諦めて丸ごと送る場合 | 読めない形（断片化 MP4・圧縮 moov・複数区間の編集リスト・stz2 など）、切っても元の 90% 以上の大きさ、途中で例外 → 今までどおり元のファイルを送る（失敗しても今より悪くならない） |
| Content-Type | 元のファイルと同じ（ftyp を元のファイルからそのまま写すので、mov は mov のまま） |

### 時刻を整数でずらす理由

点を打ったフレームの番号は `floor((time_ms − start) × fps ÷ 1000)`（約束事 17）。範囲の開始と点の時刻を同じ整数 D でずらせば
差は変わらず、フレームの番号は今と同じになる。D と本当のずれ O の差（0.5 ミリ秒以下）は、今もブラウザの時刻を整数ミリ秒に丸めているのと同じ大きさ。

### 編集リスト（elst）

新しいファイルの映像トラックには、先頭のキーフレームが時刻 0 に表示されるよう `media_time = cts(K) − dts(K)` の編集リストを書く
（B フレームのある動画では、先頭のサンプルの表示時刻が 0 でないため）。音声は同じ瞬間が 0 になる `media_time` を計算して書く。

## 3. やらないこと

- 再エンコード（案 B）。4K の動画は 4K のまま送る
- サーバー側の変更（時刻のずれを送る API など）

## 4. テスト

- 純粋な計算（サンプル表 → 各サンプルの位置・時刻、切る位置の選び方、時刻のずらし方）は `frontend/js/video/selftest.html` に足す
- 実ファイル: ffmpeg で作った動画（H.264 の B フレームあり・HEVC・回転・音声あり / なし・mov）を Node で切り出し、
  ffprobe で読めること、元の動画の時刻 t のフレームと切り出した動画の時刻 t − D のフレームが同じ画素であることを確かめる
